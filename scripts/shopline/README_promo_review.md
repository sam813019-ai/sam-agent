# 促銷活動成效分析 — 通用腳本

## 檔案

| 檔案 | 用途 |
|---|---|
| `sl_api.py` | Shopline API 共用層：重試、分頁、本機快取、欄位存取 |
| `promo_review.py` | 促銷成效分析主程式 |

## 用法

```bash
cd ~/Downloads/sam-agent/scripts/shopline

# 1) 找活動 ID（可加關鍵字過濾）
python3 promo_review.py --list
python3 promo_review.py --list 超取

# 2) 跑分析（期間預設讀活動設定的起訖）
python3 promo_review.py --id 6a965c1a3a69b678c7046b91

# 3) 自訂
python3 promo_review.py --id <ID> \
    --period 2026-10-01:2026-10-31 \
    --baseline 2026-07-01:2026-09-30 \
    --out ../../data/promo-1010
```

**產出**：`<out>/analysis.txt`（純文字完整統計）＋ `<out>/summary.json`（機器可讀，供產報告用）

## 分析邏輯

**三層母數**，少算一層比率就會失真：

| 層級 | 定義 |
|---|---|
| `all` | 全站付費訂單（僅背景參考） |
| `scope` | 活動**平台限制**內的訂單 ← 算占比的正確分母 |
| `elig` | scope 內又命中**物流限制＋金額門檻＋件數門檻**者 = 真正符合資格 |

**預設排除**：已取消訂單、NT$0 訂單（體驗組索取單，`--keep-zero` 可保留）

**觸發偵測**：以訂單明細 `item_type=Gift` 且 `promotion_id` 相符逐筆比對。

## 腳本會自動警告的四件事

1. **觸發率 100%** —— 贈品自動附加且無門檻時，領取率無法衡量吸引力，要看「符合資格占比」的變化
2. **觸發數 > 符合資格數** —— 活動的物流／平台限制未生效，後台設定要查
3. **期間長度不同** —— 自動改用日均營收比較
4. **系統 use_count 與比對數不一致** —— 系統值可能含已取消訂單

## 已知限制

- **折扣／免運型活動無法逐筆回溯**。這類活動不會在訂單明細留下可比對項目，只能參考系統 `use_count`。腳本會明講，並改以「符合資格占比」作為成效指標。
- **預設對照期為活動起月往前三個月**。活動若橫跨月份或只有十幾天，請用 `--baseline` 自訂，並看日均欄位。
- **贈品成本需自行登錄**。Shopline 的贈品成本欄位若為 0，ROI 只能用市價推估。

## 快取

訂單依期間快取於 `data/.sl_cache/`，重跑同一期間不會重打 API。要強制重抓加 `--no-cache`。
⚠️ 快取目錄已列入 `.gitignore`（內含顧客資料）。
