## LINE Pay 付款連結（2026-09-29 上線）

HERA 的 LINE Pay 商店是 **QR 收款（線下）**，商店代號 `ipa_E223614.QR`，**沒有 Channel ID / Secret，不能串 Online API**。
但把商家 QR 解碼後是一個網址，客人在 LINE 裡點得開 → 做成按鈕當過渡方案。

**2026-09-29 改版：LINE Pay 一鍵回報**。原本要客人填交易序號，但付完會直接跳回頁面、根本記不住，
改成回報表單最上面先選付款方式（有 `linepay_url` 才出現，**預設 LINE Pay**）：

- **💳 LINE Pay**：只顯示金額＋複製金額＋「1️⃣ 開啟 LINE Pay 付款」，回來按
  「2️⃣ 我已完成 LINE Pay 付款 NT$X」就送出，**不用填任何欄位**（截圖選填）
- **🏦 銀行轉帳**：維持原本的後五碼／截圖擇一

後端 `hasPaymentEvidence(last5, proofUrl, method)` 對 `method==='linepay'` 直接放行——
證據本來就是給老闆對帳用的，LINE Pay 是到後台比金額＋時間，不需要客人提供。
回報時寫 **訂單表 T 欄「付款方式」**（LINE Pay／銀行轉帳），後台待核對卡片顯示綠色

## 多筆訂單併箱：待出貨分組 ＋ 第二筆起免運（2026-09-28 上線）

一位客人在同一檔陸續下多筆訂單時，原本會重複收運費、後台要按多次出貨、客人收到多則通知。

**① 待出貨自動分組**（`getReadyToShipGroups`）
分組條件三者全中才併：**同一 userId ＋ 收件人/電話/門市/店號完全相同 ＋ 都未出貨**。
門市不同就不併（真的要寄兩箱）。卡片顯示「📦 N 筆訂單・同箱出貨」、藍框、列出各筆編號與金額，
按「整組出貨（N）」一次標記完並**只推一則通知**（訊息列出所有訂單編號）。
每筆旁邊仍有「單獨出貨」可個別處理。標頭顯示「N 箱（M 筆訂單）」。
API `?view=ship` 回 `items`（分組）＋`orderCount`；PATCH 支援 `orderIds` 陣列。

**② 同檔第二筆起免運**（`hasOpenOrder()`）
下單時查這位客人本檔是否已有「未取消且未出貨」的訂單，有就 **運費 0**。
前一筆若已出貨則照常收費（那是真的另外寄一箱）。
免運優先序：**自取 > 併箱 > 滿額門檻**。
新增 `GET /api/open-order?userId=` 讓下單頁**事前**就顯示「與您先前的訂單併箱寄出，本筆免運費」，
購物車金額那行也標「運費（併箱免運）」。⚠️ 實際金額一律以下單 API 後端計算為準。

**2026-09-28 現況**：37 筆待出貨剛好都是不同客人，分成 37 箱，暫時看不到併箱效果；
10 月連線陸續上新品後才會開始出現。

**尚未做**：到店付款（客人自取時到店再付）＋叫貨統計第三口徑——使用者要再討論後決定。
