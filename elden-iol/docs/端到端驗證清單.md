# 端到端驗證清單（必須真人操作）

Task 12 Step 8。subagent 與自動測試都做不到這幾步：Cloudflare 挑戰要真人過，
Chrome 擴充功能要真人載入，最終欄位要真人肉眼核對。

## 前置

1. `cd elden-iol && npm run build`
2. Chrome 開 `chrome://extensions` → 開啟右上「開發人員模式」→「載入未封裝項目」→ 選 `elden-iol/dist/`
3. 部署辨識 API（Vercel），並確認 `src/sidepanel/api.ts` 的 `RECOGNIZE_ENDPOINT`
   與 `manifest.config.ts` 的 `host_permissions` 指向同一個網址

## 驗證步驟

4. 新分頁開 `https://calc.apacrs.org/toric_calculator20/Toric%20Calculator.aspx`
   （或從 ascrs.org 的工具頁進去，計算器會是跨域 iframe —— 兩種開法都要測）
   等 Cloudflare 驗證過，畫面出現表單
5. **先確認第一組 K 欄位的標籤**：畫面上第一個 K 輸入框，它的說明文字是 Flat 還是 Steep？
   - 若是 Flat（客戶說法）→ 與程式預設一致，繼續
   - 若是 Steep → 程式會自動停止填入 K 值並顯示警告，此時把這件事回報，
     改 `src/content/selectors.ts` 裡 flatK / steepK 的 id 對調即可
6. 點擴充功能圖示開側邊欄 → 按「設定」→ 填醫師名稱、選一組常用 SIA → 儲存
7. 拖入（或貼上）`elden-iol/docs/samples/iolmaster700_report_sample.jpg`
8. 確認畫面上：
   - 警告橫幅顯示眼軸不一致的英文警告
   - AL 與 WTW 標為臨界值 (!)
   - SIA 那列顯示「報告單無此欄位 → 取自設定檔」的說明
9. 選 OD（右眼），逐列核對「紙上讀到」與「將填入」兩欄
10. 按「填入計算器（不會自動計算）」，切到計算器分頁核對

## 驗收標準

官網欄位應為：

| 欄位 | 期望值 |
|---|---|
| 第一組 K（平軸） | 43.08 |
| 第一組 Axis | 96 |
| 第二組 K（陡軸） | 45.58 |
| 第二組 Axis | 6 |
| Axial Length | 24.49 |
| Optical ACD | 3.15 |
| Lens Thickness | 4.99 |
| WTW | 11.6 |
| Refraction | 0 |
| Induced Cyl | 0.2 |
| Incision Axis | 設定檔選的值（180 或 0） |
| Doctor Name | 設定檔填的醫師 |

**不該被碰的欄位：**
- A Constant、Lens Factor → 必須維持原狀（客戶決定由醫師自選 IOL Model）
- Net Corneal Astig → 唯讀，必須空白或維持網站自算的值
- **Calculate 與 Reset 必須完全沒有被觸發**

## 最終比對

手動在 `IOL Model` 下拉選 `J&J DIU`，SIA 改成 0.2 @ 135（樣本當初的條件），
再按 Calculate。結果應與 `docs/samples/barrett_toric_result_sample.jpg` 一致：

**17.5 D / DIU375 / Axis 7°**

⚠️ 若 SIA 或 IOL 型號與樣本不同，結果本來就會不一樣，不算失敗。
這一步驗的是「我們填進去的量測值是對的」，不是驗計算器本身。
