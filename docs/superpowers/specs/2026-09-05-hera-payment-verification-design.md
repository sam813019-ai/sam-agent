# HERA 訂單系統：下單後匯款核對流程

**日期**：2026-09-05
**狀態**：✅ 已實作完成（2026-09-05），build 通過，待部署
**專案**：`line-order/`（Next.js + Google Sheets + LIFF）

## 目標

客人下單後先匯款，回報後五碼或截圖，老闆核對確認才算完成預購。

匯款資訊：
- 銀行：國泰世華（013）
- 帳號：014506140928
- 提示語：匯款後填入匯款後五碼或是上傳截圖畫面或拍照核對 才算完成下單預購喔🫶

## 已確認的四個決策

| 問題 | 決定 |
|---|---|
| 匯款時機 | **每筆訂單各自匯**（非整期合併） |
| 客人回報入口 | **下單完成頁 ＋「我的訂單」頁**兩邊都有 |
| 後台核對 | **新開第 9 個頁籤「匯款核對」** |
| LINE 通知 | **只 push 給老闆**（客人回報時），不 push 客人 |

## 資料結構（方案 A：訂單表加欄位）

訂單表由 A~I 擴充到 A~M：

| 欄 | 名稱 | 值 |
|---|---|---|
| J | 付款狀態 | `待匯款` / `已回報` / `已確認` / 空白 |
| K | 匯款後五碼 | 5 位數字，或空 |
| L | 匯款截圖 | Google Drive 圖片網址，或空 |
| M | 回報時間 | ISO 字串 |

### 為什麼不動 H 欄

H 欄現有狀態（`新訂單` / `手動加單` / `已出貨` / `已取消`）被 HERA bot、`/my-orders`、叫貨統計、691 筆歷史訂單共用。付款狀態另立 J 欄，既有邏輯完全不受影響。

### HERA bot 手動加單的處理

bot 加單（直播現場，多半當場收款）**J 欄留空**，代表不走此流程：
- 後台核對頁只列 `已回報`，不會出現
- 「我的訂單」只在 J 欄有值時顯示付款徽章

## 設定分頁（新增 key）

現在只用了 `title`，新增四個：

| key | value |
|---|---|
| `payment_enabled` | `TRUE` / `FALSE`（整個流程開關） |
| `payment_bank` | `國泰世華（013）` |
| `payment_account` | `014506140928` |
| `payment_note` | 匯款後填入匯款後五碼或是上傳截圖畫面或拍照核對 才算完成下單預購喔🫶 |

改帳號、改提示語、暫停流程都只要改 Sheet，不用重新部署。

## 狀態流轉

```
LIFF 下單 ──→ J=待匯款
                 │
      客人回報（後五碼 或 截圖，至少一項）
                 ↓
              J=已回報  ──→ push 通知老闆
                 │
        ┌────────┴────────┐
   確認收款              退回重填
        ↓                    ↓
    J=已確認          J=待匯款（清空 K/L/M）
```

## 畫面

### 1. 下單完成頁（`src/app/page.tsx`）

現況只顯示訂單編號＋金額。加上：
- 匯款資訊卡：銀行、帳號（**一鍵複製**，手機必要）、應付金額
- 提示語（讀自設定）
- 回報表單：後五碼輸入框 ／ 上傳截圖，兩者至少填一項
- 送出後轉為「已回報，等待確認」

### 2. 我的訂單頁（`src/app/my-orders/page.tsx`）

- 每筆訂單顯示付款徽章：待匯款（橘）／已回報（藍）／已確認（綠）
- `待匯款` 的訂單顯示「回報匯款」按鈕，開同一張表單
- `已回報` 顯示後五碼與「等待確認中」

### 3. 後台「匯款核對」頁籤（`src/app/admin/page.tsx`）

- 預設列出當期所有 `已回報` 訂單
- 每列：回報時間、客人、訂單編號、金額、後五碼、截圖縮圖（點開大圖）
- 動作：「確認收款」／「退回重填」
- 上方摘要：待核對 N 筆、合計金額

## API

| 路由 | 方法 | 用途 |
|---|---|---|
| `/api/payment-report` | POST | 客人回報（multipart，含選用截圖） |
| `/api/admin/payment-verify` | GET | 列出待核對 |
| `/api/admin/payment-verify` | PATCH | 確認收款／退回重填 |
| `/api/admin/migrate-payment-columns` | POST | 一次性寫入 J~M 標題列 |

截圖上傳複用既有的 `uploadImageToDrive()`（Google Drive OAuth2）。

## 安全性

⚠️ `/api/payment-report` 是**公開端點**，必須驗證：
1. `orderId` 存在
2. 該訂單的 `userId` 與請求帶的 `userId` 相符 — 否則任何人都能竄改別人訂單的匯款資訊
3. 該訂單 J 欄目前為 `待匯款`（已確認的不可覆寫）
4. 後五碼格式為 5 位數字；截圖限 image/*，大小上限 5MB

## 錯誤處理

| 情況 | 行為 |
|---|---|
| 兩項都沒填 | 前端擋下，提示至少填一項 |
| 後五碼格式錯 | 前端即時提示 |
| 訂單不存在／非本人 | 400，不透露訂單是否存在 |
| 圖片上傳失敗 | 若有後五碼則仍寫入，回報「截圖上傳失敗但後五碼已記錄」 |
| Sheet 寫入失敗 | 500，前端提示重試，不清空已填內容 |
| 設定分頁沒有匯款資訊 | 退回硬編碼預設值，不讓下單流程壞掉 |

# 第二階段：運費與 7-11 取貨資訊（同日追加）

## 運費

- 每筆訂單固定 **60 元**，金額放設定分頁 `shipping_fee`（預設 60）
- **總金額含運費**（訂單表 F 欄 = 商品小計 + 60），客人匯的金額就是這個數字
- 不另外開運費欄位（老闆決定：總額含運費，不另外記）
- **訂單明細不加運費列**——那張表是叫貨統計來源，加進去會污染商品數量
- 下單頁購物車拆開顯示「商品 X ＋ 運費 60 ＝ 應付 Y」，並固定顯示
  「📦 僅限 7-11 超商取貨・每筆運費 $60」

## 取貨資訊（訂單表 N~R）

| 欄 | 內容 |
|---|---|
| N | 收件人姓名 |
| O | 電話 |
| P | 門市名稱 |
| Q | 門市店號 |
| R | 填寫時間 |

只支援 7-11 超商取貨，沒有宅配選項。
**店號採手動輸入**，不串 7-11 電子地圖（要申請商家代號＋callback，工程量大好幾倍）。

## 流程延伸

```
老闆按「確認收款」
   ↓
J=已確認 ＋ push 客人：「已收到款項，請填寫 7-11 取貨資訊」＋ LIFF 連結
   ↓
客人在「我的訂單」填姓名／電話／門市／店號  →  寫入 N~R
   ↓
push 老闆：「取貨資訊已填寫，可以出貨了」
   ↓
後台「匯款核對 → 待出貨」看得到，一鍵複製收件資訊
```

⚠️ 這是唯一會 push 客人的訊息。先前決定「只通知老闆」，此處破例是因為
不填取貨資訊就無法出貨，這則 push 有實際作用。

## 後台

「匯款核對」頁籤加 **待核對／待出貨** 切換：
- 待核對：已回報匯款，看後五碼與截圖，確認或退回
- 待出貨：已確認收款且已填取貨資訊，顯示收件資訊，一鍵複製整段貼到寄件系統

## 不做（YAGNI）

- 不做金流串接（LINE Pay／綠界）——那是擴充清單第 9 項，另案
- 不做自動比對銀行帳務——後五碼是人工核對用
- 不做多次回報的歷史紀錄——重填直接覆寫
- 不做宅配選項——只支援 7-11 超商取貨
- 不串 7-11 電子地圖——店號手動輸入
