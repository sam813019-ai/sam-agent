# 經銷後台訂購單多商品支援 — 設計規格

**日期**：2026-07-28
**專案**：`heiwei-dealer-portal`（https://heiwei-dealer-portal.vercel.app）
**目標**：讓代理商除了現有的「爆白防曬隔離噴霧」外，也能訂購新品「爆白防曬棒」。

---

## 1. 背景

現有訂購表單是單一商品設計：只有三段階梯方案（$350/30件、$300/100件、$270/500件），
Sheet「訂購單」G 欄只存方案名稱，沒有任何商品欄位。

新增品項後必須讓代理先選商品，再選該商品專屬的階梯價。

## 2. 商品與定價

| 商品 | 入門（30件起） | 進階（100件起） | 批量（500件起） |
|------|---------------|----------------|----------------|
| 爆白防曬隔離噴霧 | $350 | $300 | $270 |
| 爆白防曬棒 | $450 | $390 | $350 |

兩商品階梯門檻相同（30 / 100 / 500），僅單價不同。

## 3. 下單模式

**一張訂單一種商品。** 代理若要同時訂兩種商品，送兩張單。

理由：Sheet 維持一列一單的扁平結構，「我的訂單」、LINE 通知、對帳流程都不用改寫成明細結構。
購物車式混單留待商品數成長後再評估。

## 4. 前端設計（`js/portal.js`）

### 4.1 商品資料驅動

於檔案頂部新增 `ORDER_PRODUCTS` 常數，往後上新品只需改這一份資料：

```js
const ORDER_PRODUCTS = [
  { id: 'spray', name: '爆白防曬隔離噴霧', tiers: [
      { price: 350, min: 30,  label: '入門方案（30件以上）' },
      { price: 300, min: 100, label: '進階方案（100件以上）' },
      { price: 270, min: 500, label: '批量方案（500件以上）' } ] },
  { id: 'stick', name: '爆白防曬棒', tiers: [
      { price: 450, min: 30,  label: '入門方案（30件以上）' },
      { price: 390, min: 100, label: '進階方案（100件以上）' },
      { price: 350, min: 500, label: '批量方案（500件以上）' } ] }
];
```

### 4.2 表單流程

順序：訂購人資料 → **商品選擇** → 方案選擇 → 訂購數量 → 匯款 → 發票 → 協議。

- 商品選擇為 radio 卡片，沿用既有 `.plan-grid` / `.plan-item` 樣式，價格欄顯示「$xxx 起」。
- 未選商品前，方案區顯示提示文字「請先選擇商品」，不 render 任何方案。
- 選定商品後，依 `tiers` 動態 render 方案卡片。

### 4.3 切換商品必須重置

切換商品時清空已選方案、清空數量、隱藏金額試算、清空三個 hidden field。

**這是本次最關鍵的正確性要求**：若不重置，代理選了噴霧 $270 再改選防曬棒，
殘留的單價會讓總金額算錯，且錯誤金額會直接寫進 Sheet 與 LINE 通知。

### 4.4 送出資料

`data` 物件新增 `product_name` 欄位（值取自選定商品的 `name`）。
`plan_label`、`unit_price`、`quantity`、`total_amount` 語意不變。

送出前驗證：未選商品時擋下並提示。

### 4.5 我的訂單顯示

訂單卡片在方案名稱上方加一行商品名，來源為 GAS 回傳的 `product`。

## 5. 後端設計（`gas/Code.gs`）

### 5.1 Sheet 欄位變更

「訂購單」在 **G 欄插入「商品」**，G 之後全部右移一格：

| 欄 | 變更前 | 變更後 |
|----|--------|--------|
| A–F | 時間 / LINE UID / 姓名 / 電話 / Email / 地址 | 不變 |
| G | 方案 | **商品** |
| H | 單價 | 方案 |
| I | 數量 | 單價 |
| J | 總金額 | 數量 |
| K | 匯款後五碼 | 總金額 |
| L | 發票類型 | 匯款後五碼 |
| M | 發票抬頭 | 發票類型 |
| N | 統編 | 發票抬頭 |
| O | 狀態 | 統編 |
| P | 貨運方式 | 狀態 |
| Q | 貨運編號 | 貨運方式 |
| R | — | 貨運編號 |

需在 Google Sheet 手動於 G 欄插入一欄，既有列會自動右移。

`SheetScript.gs` 只操作「申請名單」與「授權書申請」兩個分頁，不碰「訂購單」，
因此本次欄位變更不影響授權書核准流程。

### 5.2 舊資料相容

舊訂單插欄後商品欄為空。`getMyOrders` 讀到空值時 fallback 為 `'爆白防曬隔離噴霧'`
（改版前的訂單必定是噴霧）。

### 5.3 程式變更

- `handleOrder`：`appendRow` 於方案前插入 `data.product_name`；建表 header 同步加「商品」；
  LINE 通知訊息新增「商品：」一行。
- `getMyOrders`：G 之後索引全部 +1（方案 6→7、數量 8→9、總金額 9→10、
  狀態 14→15、貨運方式 15→16、貨運編號 16→17），回傳新增 `product` 欄位。

## 6. 部署需求

GAS `Code.gs` 修改後**必須重新部署 Web App**（管理部署 → 編輯 → 新版本），
否則前端送出的 `product_name` 不會被寫入。

前端由 Vercel 自動部署。

## 7. 驗證項目

1. 選噴霧 → 三段價顯示 350/300/270；選防曬棒 → 450/390/350
2. 選防曬棒批量方案（$350）後改選噴霧 → 方案與數量清空、金額試算歸零
3. 數量低於門檻時 `min` 屬性擋下送出
4. 送出後 Sheet G 欄寫入正確商品名、後續欄位未錯位
5. LINE 通知含商品名
6. 「我的訂單」新單顯示商品名；舊單顯示「爆白防曬隔離噴霧」
7. 舊單的狀態、貨運方式、貨運編號在插欄後仍正確顯示
