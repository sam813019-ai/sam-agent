## 目標
讓陳育慶可以在 Google 試算表隨時調整轉盤獎項的**機率、每日限量、名稱、組數（增減格）、啟用與否**，約 60 秒內自動生效，不需改程式或重新部署。同時確保展期當天穩定：讀取加快取、Sheets 失效時自動用內建預設。

## 資料來源：新分頁「獎品設定」
在既有試算表（id `1jKz4OHr2ooYz3nY21EC8Yyl9buX_xeFhUW-p_ec_5L8`）新增分頁「獎品設定」。欄位（A–H）：

| 欄 | 名稱 | 說明 |
|----|------|------|
| A | 代碼(id) | 每日限量計數依據，建立後勿改；留空則自動由名稱生成 |
| B | 啟用 | 「是」才出現在轉盤；「否」= 暫時隱藏 |
| C | 獎項名稱 | 完整名稱（推播/紀錄用） |
| D | 轉盤顯示文字 | 盤面上的字，可用 Alt+Enter 換行 |
| E | 權重 | 中獎權重，不必湊 100，系統自動換算比例 |
| F | 每日限量 | 留空=不限 |
| G | 兌換說明 | 客人看到的兌換方式 |
| H | 保底獎 | 標「是」的那項；當某實體獎當日發完，改中此獎（保底導購） |

顏色不放進試算表：由系統依 HEIWEI 灰綠色系，按格數自動交替配色。

## 元件

### `lib/prize-config.js`（新）
- `getPrizeConfig()` → `{ prizes: [{ id, full, label, weight, dailyCap, redeem, color, text }], fallbackId }`
- 流程：先讀 KV 快取 `prizes:config`（TTL 60 秒）→ 命中則用；未命中 → 讀「獎品設定」分頁 → 解析（過濾「啟用=是」、代碼留空則由名稱生成、每日限量空=null）→ 依索引配色 → 寫回 KV 快取 60 秒。
- **備援**：讀表失敗或回傳 0 筆有效獎項 → 回傳內建 `DEFAULT_PRIZES`（即 `prizes.js`）。
- 配色：內建 HEIWEI 色盤（灰綠交替），依索引取色並自動決定文字深/淺色。

### `prizes.js`（保留為備援預設）
- 匯出 `DEFAULT_PRIZES` 與 `FALLBACK_ID`，內容同上初始 9 格，供 Sheets 失效時使用。

### `api/prizes.js`（新）
- `GET` → 回傳前端畫盤所需的精簡陣列 `[{ id, label, color, text }]`（來自 `getPrizeConfig()`）。供瀏覽器載入時抓取。

### `api/draw.js`（改）
- 改用 `getPrizeConfig()` 取得 `prizes` 與 `fallbackId`，據以加權抽獎、查每日限量（KV `stock:<date>:<id>`）、取兌換說明、保底切換。其餘（驗身分、擋重複、發碼、寫 KV、寫 Sheet、推播）不變。

### `public/index.html`（改）
- 載入時 `fetch('/api/prizes')` 取得獎項顯示設定，**動態建構 `DISPLAY` 並畫盤**（格數由回傳筆數決定，`SEG = 360/N`）。
- `spinTo` 以回傳陣列中 `id` 的索引定位扇形。
- **備援**：fetch 失敗時用頁面內建的預設 `DISPLAY`（現行 9 格），保證離線也能顯示。

## 資料流
- 載入：GET /api/prizes →（KV 快取 or Sheets）→ 畫盤。
- 抽獎：POST /api/draw → getPrizeConfig（同一份快取）→ 加權抽 + 每日限量 → 發碼 → 存 KV → 寫 Sheet → 推 LINE → 回傳獎項。
- 前端盤面與後端機率讀同一份設定，永遠一致。

## 錯誤處理
- Sheets 讀取失敗 / 空 → 用 `DEFAULT_PRIZES`（前後端各有內建預設）。
- 快取層用 KV，跨 serverless 實例共用，60 秒 TTL，避免尖峰狂打 Sheets API。
- 代碼變更會使該日限量計數重置（可接受，屬罕見操作），文件提醒使用者「代碼建立後勿改」。

## 測試
1. 讀表解析：本機以 service account 讀「獎品設定」→ 驗證 9 筆、權重/限量/保底正確。
2. 快取：連續兩次呼叫 getPrizeConfig，第二次應命中 KV（不打 Sheets）。
3. 備援：暫時給錯 SHEET id / 清空分頁 → 應回傳 DEFAULT_PRIZES。
4. `/api/prizes` 線上回傳 9 筆含 color。
5. 前端動態畫盤：改成 5 格 / 改權重 → 60 秒後重載，盤面更新且顏色協調。
6. 端到端：真抽一次，盤面獎項與後端回傳一致、Sheet 有紀錄、推播正常。

## 非目標（YAGNI）
- 不做後台編輯 UI（試算表即編輯介面）。
- 不做即時（<60 秒）更新；60 秒快取足夠。
- 不把顏色開放給使用者設定（自動配色）。
