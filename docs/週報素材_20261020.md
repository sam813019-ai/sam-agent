# 重要發現與風險

**① LINE 綁定 ≠ 推得到**
實測 B 軌名單 171 位有 `line_id`，實際推得到僅 **141 位（82.5%）**，30 位（17.5%）因封鎖或刪好友而觸及不到，這批累計消費 NT$385,044，含小C NT$42,451、林筑偉 NT$32,881 等老客。
→ 轉換率分母必須用「實際送達」，用名單人數會低估兩成。

**② LINE userId 跟 Provider 綁定，跨帳號不通用**
同一人在 @heiwei 與 HERA（@211izvqf）底下是兩組完全不同的 userId。Shopline 若存到別家 Provider 的 ID，@heiwei 推播一律 404。排查推播失敗時這是第一個要查的。

**③ Shopline 的 LINE 登入用 Email 配對會員，對不上就開新帳號**
歷史訂單、點數、等級會留在舊帳號。A 軌要發給 2,427 位，若 LINE 註冊信箱 ≠ 官網購物信箱會產生重複帳號。已在文案加註提醒，後續需人工併戶。

**④ `line_id` 無法用 Open API 寫入**
`PUT /v1/customers/{id}` 只吃 name/email/phone/birthday/gender。要搬綁定只能：後台解除 → 調整 Email 讓配對得上 → 請本人用 LINE 重新登入。

**⑤ @heiwei 的 webhook 已被 Shopline 佔用**
指向 `front-admin.shoplineapp.com`，一個 channel 只能有一個 webhook。若改成自建 bot，Shopline 的 LINE 訊息中心、社群綁定、訂單通知會全部斷掉。故自動回覆只能用 LINE OA 後台內建功能。
